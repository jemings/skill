# agent-clinic — 저장소 컨텍스트·문서 위생 점검

## 원칙

CLAUDE.md/AGENTS.md는 세션마다 적재되는 상시 비용이고, 공개 문서(README/docs/**)는
온디맨드지만 신뢰 비용이다 — 방치된 오류는 다음에 그 문서를 읽는 사람이나
에이전트를 그대로 오도한다. 목표는 삭제가 아니라 **재배치**: 세션마다 필요한
것과 가끔 필요한 것을 분리하고, 코드와 어긋난 서술은 코드 기준으로 바로잡고,
더 이상 유효하지 않은 산출물만 삭제한다. 범위는 문서·설정·저장소 위생으로
한정 — 애플리케이션 코드·동작은 건드리지 않는다.

절대 불변: 실제로 유효한 동작 설명은 이동은 되어도 사라지면 안 된다(예외:
완료되어 더 이상 유효하지 않은 일회성 산출물). 문서 간 링크는 이동·삭제 후에도
깨지면 안 된다.

CLAUDE.md 안의 서술 하나하나는 다음 네 갈래 중 하나로 귀결돼야 한다 — 사람
대상 개요·설치·기능 설명이면 README(또는 공개 docs)로 옮기고, 설명하지
않아도 당연한 내용(프레임워크 기본 동작, 일반 상식)이면 그냥 삭제하고,
가끔만 필요한 디테일이면 참고 문서 + 한 줄 링크로 옮기고, 세션마다 몰라선
안 되는 비직관적 불변식·함정만 CLAUDE.md에 남긴다. AGENTS.md는 별도 내용을
두지 않고 Claude Code의 import 문법으로 `@CLAUDE.md` 한 줄만 남겨 CLAUDE.md를
그대로 가리키게 한다 — 두 파일이 따로 유지보수되는 걸 막는다.

## 1단계 — 진단 (read-only, 편집 전 필수)

- **컨텍스트 파일 비대 점검**: `wc -lc CLAUDE.md AGENTS.md`(프로젝트 루트
  기준). AGENTS.md가 `@CLAUDE.md` 한 줄이 아니라 CLAUDE.md 내용을 중복·부연
  하고 있으면 정리 대상. CLAUDE.md는 문단 단위로 "원칙"의 네 갈래(README행
  / 삭제 / 참고문서행 / 세션 필수) 중 어디로 가야 하는지 표시한다 — 특히
  설치·기능·개요처럼 사람 대상인데 CLAUDE.md에 남아있는 문단, 설명 없이도
  당연한 문단을 놓치지 않는다.
- **사실 기준 우선순위로 문서-코드 대조**: 실제 동작의 근거는 이 순서로
  삼는다 — ① 라우터/서비스(핵심 로직) 코드 ② 데이터 모델/마이그레이션
  ③ 실제 화면·요청 흐름 ④ `.env.example`/config/compose ⑤ 테스트·최근
  changelog. 이 순서와 다른 설명이 문서에 남아있으면 대조 대상.
- **낡은 문서 탐지**: 완료된 마이그레이션/이관 가이드, 특정 로컬 스택에만
  의존하는 일회성 시험 문서, 지금과 다른 인증 방식·프레임워크·API 형태를
  설명하는 문서.
- **연동 참조 점검**: 문서가 언급하는 스크립트·훅·슬래시커맨드·MCP 서버·외부
  서비스 연동이 리포 어디에 실존하는지 대조한다(언급된 이름·경로를 리포
  전체에서 재검색). 실존 근거를 못 찾으면 broken 연동 후보 — 못 찾았다는
  사실만으로 바로 지우지 않고 2단계에서 사용자 확인을 받는다.
- **추적 위생**: `git ls-files -ci --exclude-standard` 로 `.gitignore`에는
  있지만 여전히 git에 tracked 인 파일을 종류를 가리지 않고 찾는다(에디터
  설정, 스펙/플랜 캐시 등 — gitignore 규칙 추가 이전에 커밋된 잔재가
  흔하다). 아직 `.gitignore`에 없는데 커밋되면 안 되는 개인화·로컬 전용
  디렉토리(`.idea/`, `.vscode/` 등)도 함께 표시하고, `.gitignore` 자체의
  중복·주석 처리된 규칙도 확인.
- **완료된 플래닝 산출물**: 위 추적 위생에서 찾은 스펙/플랜 디렉토리 중
  이미 구현이 끝나 더 이상 유효하지 않은 문서가 있는지, 애초에 로컬 전용
  관례(예: superpowers 류 스펙/플랜 스킬의 산출물)로 커밋되면 안 되는
  디렉토리인지 구분한다.
- **링크 무결성**: 문서 내 상대경로 마크다운 링크가 가리키는 파일이 실제로
  존재하는지.

산출: 범주별 문제 목록 — 컨텍스트 파일 비대(네 갈래 분류 포함) / 문서-코드
불일치 / broken 연동 참조 / 추적되면 안 되는 파일 / 삭제 후보 / 깨진 링크.
각 항목에 근거(대조한 코드 위치, 재검색 커맨드 결과 등)를 명시한다.

## 2단계 — 계획

- 단일 파일 몇 줄 수정이면 바로 3단계로 진행한다. 단, 실제 파일 삭제나
  `git rm --cached` 같은 언트랙을 수반하는 작업은 대상이 하나뿐이라도 예외
  없이 사용자 확인 후 실행한다.
- 여러 문서에 걸친 재정비(예: 공개 문서 세트 전체 최신화)면 실행 전에 설계
  문서 + 태스크 단위 플랜을 먼저 작성한다. 프로젝트에 스펙/플랜 스킬(예:
  superpowers)이 이미 있으면 그 컨벤션을 따르고, 없으면
  `references/reorg-plan-template.md`를 쓴다.
- 계획에는 유지할 문서/삭제할 문서/각 태스크의 검증 커맨드를 명시하고,
  적용 전에 사용자 확인을 받는다. 삭제 대상은 특히 — 되돌리기 어렵다.
  broken 연동 참조와 로컬 전용 디렉토리(스펙/플랜 캐시 등) 삭제는 다른
  무엇보다 먼저 확인이 필요하다 — 아직 안 끝났거나 못 찾은 곳에서 여전히
  쓰이고 있을 수 있다.

## 3단계 — 적용

- **컨텍스트 파일 다이어트**: 1단계에서 분류한 네 갈래대로 옮긴다 — 사람
  대상 내용은 README/공개 docs로, 당연한 내용은 그냥 삭제, 가끔 필요한
  디테일은 별도 참고 문서(`docs/*.md`)로 옮긴 뒤 한 줄 포인터만 남기고,
  세션 필수 불변식만 CLAUDE.md에 남긴다. AGENTS.md는 다른 내용 없이
  `@CLAUDE.md` 한 줄로 축소한다.
- **문서-코드 정합화**: 1단계 대조에서 드러난 사실 오류·누락을 코드 기준으로
  고친다.
- **낡은 문서 삭제**: 승인된 삭제 대상만 제거하고, 그 문서를 가리키던 링크를
  대체 문서로 바꾸거나 제거한다.
- **연동 참조 정리**: 1단계에서 확인한 broken 연동 서술은 사용자가 승인한
  것만 제거하거나 낡았다고 표시한다.
- **추적 위생**: 1단계에서 찾은 tracked-but-ignored 파일을 언트랙
  (`git ls-files -ci -z --exclude-standard | xargs -0 -r git rm -r --cached --`
  — 경로에 공백이 섞여도 깨지지 않도록 `-z`/`-0`로 null-구분해서 넘긴다)
  + 아직 `.gitignore`에 없는 개인화·로컬 전용 규칙 추가(재유입 방지) +
  중복·주석 처리된 규칙 정리.
- **완료된 산출물 정리**: 용도가 끝난 스펙/플랜 문서·마이그레이션 가이드
  삭제. 애초에 로컬 전용이어야 하는 디렉토리(스펙/플랜 스킬 산출물 등)는
  삭제에 그치지 않고 `.gitignore`에도 등록해 재유입을 막고, 그 디렉토리를
  가리키던 문서 링크도 함께 정리한다.
- 태스크마다 별도 커밋 — 문서 변경과 설정(.gitignore) 변경을 섞지 않는다
  (Conventional Commits: `docs:`/`chore:`). 프로젝트에 changelog 정책이
  있으면 기록한다.

## 4단계 — 검증

- 링크 재검사, env var/API 경로를 실제 코드와 재대조, 알려진 낡은 표현
  (구 인증 방식·구 프레임워크 이름 등) 잔여 검색, `git diff --check`(공백
  오류), 있으면 애플리케이션 테스트 실행 — 문서 변경이 동작을 건드리지
  않았음을 확인한다.
- 2단계에서 만든 설계/플랜 문서가 로컬 전용 산출물이라면, 완료 후 삭제(또는
  애초에 로컬 전용 디렉토리에 있어 커밋되지 않았는지 재확인)한다.
- `git ls-files -ci --exclude-standard`가 다시 비어 있는지 재확인해 언트랙 +
  `.gitignore` 조치가 실제로 재유입을 막는지 검증한다.

## 안 하는 것

- 애플리케이션 코드·동작 변경 — 범위는 문서·설정·저장소 위생.
- 검증 없는 대량 삭제, 사용자 확인 없는 삭제 실행.
- 유효한 동작 설명을 사라지게 하는 것 — 재배치는 되지만 삭제는 승인된
  대상만.
- 여러 성격의 변경을 한 커밋에 섞는 것.
