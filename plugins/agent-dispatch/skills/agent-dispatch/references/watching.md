# 지켜보기 -- 사람이 넣어야 하는 PR, 남의 PR

SKILL.md 9단계에서 읽는다. 기본 흐름에서는 네가 PR 을 넣으므로 지켜볼 것이 없다. 다음 둘이 있을 때만 건다.

- **이 실행의 PR**: `land.sh` 가 `NEEDS_HUMAN` 을 낸 PR(보호 규칙이 사람의 승인을 요구한다). 단계는 `사람 병합 대기` 다.
- **남의 PR**: 범위 안의 남은 이슈를 막고 있는데 다른 세션이 연 열린 PR. 그 병합이 다음 frontier 를 연다.

## 건다

Bash 의 `run_in_background` 로 띄우고 task id 를 상태 블록의 "지켜보기"에 적는다.

```sh
bash "${CLAUDE_SKILL_DIR}/scripts/wait-prs.sh" --repo <owner>/<repo> [--since <PR>=<커서>]... [--other <남의 PR>]... <이 실행의 PR>...
```

- 스크립트는 일이 생긴 차례에 그 일을 모두 내고 끝난다. 끝나면 harness 가 너를 다시 부른다. 따로 폴링하지 않는다.
- **한 번 깨어나면 끝난다.** 일을 처리할 때 맨 먼저 남은 목록으로 다시 건다. 두 목록이 다 비었으면 걸지 않는다.
- 지켜보기는 하나만 둔다. 목록이 바뀌면 `TaskStop` 으로 멈추고 새 목록으로 다시 건다(멈춘 task 의 알림은 무시한다).
- `--since <PR>=<커서>` 의 커서는 그 PR 에서 마지막으로 읽은 피드백의 시각이다. 진행 목록의 그 줄에 `피드백 커서` 로
  적고 이어 싣는다. 처음이면 싣지 않는다.
- 사람이 먼저 알려 오면("merged", "PR 에 수정 요청 남겼어") 지켜보기를 멈추고 같은 처리를 한다.

## 일마다 처리한다

- **`MERGED` -- 이 실행의 PR**: 다시 걸고, `land.sh --cleanup --repo <o>/<r> --pr <P> --issue <N>` 으로 뒷정리한다.
  그다음 SKILL.md 8단계의 `LANDED` 처리를 그대로 한다.
- **`MERGED`/`CLOSED` -- 남의 PR**: 다시 걸고, 상태 블록의 "처리한 착륙"에 적고 1단계로 돌아간다.
- **`CONFLICTING`**(이 실행의 PR): 목록에서 빼고 다시 건다. Rebase 를 보낸다(단계 `rebase`). 돌아오면 7단계 검수 뒤
  `land.sh` 를 다시 돌린다.
- **`FEEDBACK` -- 이 실행의 PR**: 목록에서 빼고 다시 건다. 커서 뒤 피드백을 읽는다.

  ```sh
  bash "${CLAUDE_SKILL_DIR}/scripts/wait-prs.sh" --show --repo <owner>/<repo> [--since <PR>=<커서>] <PR>
  ```

  커서를 읽은 것의 최댓값(`at`)으로 옮기고 가른다.
  - **수정 요청**: Fix 로 보낸다(항목마다 URL, `path:line`, 본문). 되돌림, 리뷰 라운드에 세지 않는다. 돌아오면 7단계.
  - **계약을 바꾸는 요청**: 계약서를 먼저 고치고 "사용자 결정(날짜)"으로 적은 뒤 Fix.
  - **질문**: 보고로 답하고(PR 에는 쓰지 않는다) 목록에 되넣는다. **승인 따위**: 되넣는다.
  - **애매하면**: `AskUserQuestion` 으로 묻는다. 답이 올 때까지 목록 밖에 둔다.
- **`CLOSED` -- 이 실행의 PR**: 다시 걸고, 사람에게 이유를 묻는다. 답에 따라 다시 계약하거나 범위에서 뺀다.
- **`GH_FAILING`**: 번호가 틀렸으면 고쳐 다시 건다. 인증, 네트워크 문제면 사람에게 알리고 `--interval 300` 으로 다시 건다.
- **`TIMEOUT`**(`--timeout` 을 줬을 때만): 다시 건다. **exit 2**: 인자를 고쳐 다시 건다.

일은 PR 마다 한 번만 처리한다. "처리한 착륙"에 있는 PR 의 일이 다시 오면 건너뛴다.
