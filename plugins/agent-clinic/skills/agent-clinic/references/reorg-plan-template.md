# 문서/저장소 재정비 플랜 템플릿

superpowers 같은 스펙/플랜 스킬이 없는 프로젝트에서 agent-clinic 2단계가
여러 문서에 걸친 재정비를 계획할 때 쓰는 최소 템플릿이다. 태스크는 체크박스
(`- [ ]`)로 추적하고, 태스크 하나가 끝날 때마다 커밋한다.

```markdown
# <프로젝트> 문서 재정비 플랜

**목표:** <한 문장 — 무엇을 현재 상태와 맞출 것인가>

**배경:** <문서가 왜 낡았는지 — 마지막 최신화 시점 vs 현재 구현 범위>

**비목표:** <애플리케이션 코드 변경 안 함 / 버전 출시로 취급 안 함 / 과거
릴리스 기록 소급 수정 안 함 등>

**사실 기준 우선순위:** ① 라우터/서비스 코드 ② 모델/마이그레이션 ③ 실제
화면·요청 흐름 ④ env/config/compose ⑤ 테스트·changelog

## 유지·갱신할 문서

- `<path>`: <이 문서가 다루는 범위 1줄>

## 삭제할 문서

- `<path>`: <왜 더 이상 유효하지 않은지>

## 반드시 바로잡을 현재 동작

- <코드 대조로 확인한, 문서가 틀리게 서술하고 있는 사실>

## Task N: <제목>

**Files:**
- Modify: `<path>`
- Delete: `<path>`

- [ ] **Step 1: 기준선 기록** — 삭제/변경 대상 참조를 grep으로 확인

  ```bash
  rg -n '<제거될 용어>' . --glob '*.md'
  ```

  Expected: <기대 결과>

- [ ] **Step 2: 수정 적용**

- [ ] **Step 3: 검증**

  ```bash
  rg -n '<낡은 표현>' <변경된 파일>
  git diff --check
  ```

  Expected: <기대 결과>

- [ ] **Step 4: 커밋**

  ```bash
  git add <files>
  git commit -m "docs: <설명>"
  ```

## 완료 기준

- 승인된 삭제 대상만 제거되어 있다.
- 유지 대상 문서가 모두 존재하고 최신 동작을 반영한다.
- 문서 간 상충 설명이 없다.
- 링크·검증 커맨드·테스트가 통과한다.
```
